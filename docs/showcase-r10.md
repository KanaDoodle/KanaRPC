# RPC 治理控制台

通过可调负载和请求决策时间线，观察服务端过载控制、流式取消与优雅关闭。控制台直接使用 KanaRPC SDK、本机 QUIC 连接和定时器/槽位负载，启动时自动创建服务端、客户端与负载发生器。

## 启动

```sh
go run ./cmd/showcase
```

打开 `http://127.0.0.1:8080`。端口被占用时使用 `go run ./cmd/showcase -listen 127.0.0.1:8090`。Ctrl+C 停止 HTTP 接纳并回收本次进程的 RPC 和负载。启动无需 GPU、etcd、容器或 npm；首次构建需要 Go 依赖缓存或模块下载条件。

## 三个操作流程

1. **过载与恢复**：点击“制造过载”，观察慢方法的并发调整、客户端反馈限流、排队和快慢请求 p95。调整请求速率、慢请求比例、处理耗时和后端槽位后，点击“应用负载”；“恢复容量”用于观察容量变化后的行为。
2. **流式取消**：点击“停止新负载”，再“开始流式请求”。片段到达后点击“取消流式请求”，查看取消控制、处理器返回和资源释放的记录。
3. **关闭与交付故障**：点击“优雅关闭”，查看在途请求完成及关闭报告。新建会话后点击“注入未回执故障”，专用故障客户端会接收终态并扣留 ACK，随后执行关闭；页面分别展示资源退出和交付故障。

固定上限与自适应模式通过“新建会话”切换；切换时结束旧负载，保留旧会话摘要与累计交付故障。最多保存 8 个历史摘要，累计故障独立于摘要淘汰；请求列表标注所属会话。记录保存在当前进程内。

## 指标与时间线

生命周期栏分别展示累计接纳、当前排队、当前执行、终态收尾与累计释放。结果面板列出请求成功/失败、接纳拒绝、反馈限流、发生器丢弃和累计交付故障，便于对照压力来源。

客户端 p95 使用后台负载最近 256 次调用，包含失败；控制器使用处理器驻留时间窗口 p90。流处理器内部的信用等待计入驻留时间。固定模式保持配置上限，自适应模式按有效样本与需求调整，具体策略见 [过载治理](governance-r7c.md)。

时间线按本地捕获序号展示接纳、排队、执行、数据发送、取消、终态、ACK 与退休。记录器有界并支持采样；页面同时提供覆盖、争用丢弃和采样跳过计数，事件缺失的解释见页面“运行与状态说明”。ACK 表示协议终态回执，业务提交由应用确认。

## 接入决策事件

```go
journal, err := kanarpc.NewTraceRecorder(kanarpc.TraceConfig{
    Capacity: 4096, SampleEvery: 1,
})
// 检查 err，再显式启用；Trace 默认 nil。
server, err := kanarpc.NewServer(kanarpc.ServerConfig{Trace: journal})
snapshot := journal.Snapshot(lastSequence, 512)
```

`RequestTrace(ctx)` 返回开启记录后的本地 channel/request/method 标识：TCP 的 channel 是记录连接，QUIC 的 channel 是原生请求流。记录内容包含阶段、原因与状态码，省略请求体、响应体和回执 token。客户端接纳失败通过反馈统计和调用错误展示。

- 记录容量 16–16384，默认 4096；单次读取上限 1024。同一 channel/request 对采用稳定采样。
- RPC 写事件使用 TryLock，忙时跳过并累计 Dropped；Overwritten 与 SampledOut 分别统计。没有外部 callback 或观察器 goroutine。
- 前端最多保留 240 个请求、每请求 96 个事件、90 个图点；每条流显示最近 32 个块。
- HTTP 增量获取事件；连接错误时保留上次数据，过期响应通过操作版本隔离。

## 实现路径

| 层次 | 代码与职责 |
| --- | --- |
| 本地观测 | `trace.go`：可选记录器、阶段事件和 Context 关联；协议字段保持原有格式 |
| 会话与负载 | `cmd/showcase/app.go`：复用 Governance、FeedbackStats 与 DrainWithReport，限制负载发生器并发 |
| 控制接口 | `cmd/showcase/http.go`：状态快照、负载配置、流与关闭操作，校验 Host/Origin |
| 故障注入 | `cmd/showcase/badclient.go`：使用独立 QUIC 客户端构造未回执交换 |
| 页面 | `cmd/showcase/web`：离线资源、负载控制、流片段、请求列表与时间线 |

## 运行配置与验证

HTTP 监听范围为 loopback；会话重启与关闭采用互斥操作门，并发操作返回冲突。操作结束后可再次新建会话。控制台为讲解期间的空闲连接单独配置 30 分钟 QUIC idle timeout，框架默认仍为 30 秒；长时间空闲或连接失效后可新建会话。

控制台已验证本机 HTTP + QUIC 的过载、取消、正常关闭、未回执故障和历史保留流程。真实双机、WAN 与模型推理性能尚未验证。部署要求、回执语义和观测范围统一见 [使用约束](operating-notes.md)；具体检查、截图与失败记录见 [R10 报告](verification/showcase-r10/report.md)。
