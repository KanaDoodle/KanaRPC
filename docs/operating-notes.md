# 使用约束与部署要求

本页集中说明接入、部署和解释运行结果时需要遵守的契约。各组件文档提供配置、实现机制与复现入口。

## 协议与业务责任

KNR2 v2 使用 JSON 记录，提供普通调用与服务端流式调用。新旧协议端点应显式分离。框架按调用者指定的端点与传输发送请求；业务重试、幂等键、服务端去重和任务恢复由应用安排。调用失败后，应用应结合业务状态判断执行结果，避免重复提交。

## 安全配置

TLS/QUIC 要求可信 CA、ServerName 以及需要时的客户端证书；mTLS 认证连接身份，方法与租户授权由应用实施。明文 TCP 适用于受信任链路，跨信任边界部署应使用认证传输。压力反馈是经校验、可过期的接纳建议，适用于受信任服务端；多连接客户端的建议总和并非分布式配额。

治理控制台只监听 loopback，校验 Host 和控制请求的 Origin。它面向本机操作，未提供远程管理鉴权，部署时应保持本机访问范围。本地证书私钥、环境配置和凭据应通过仓库外的安全配置提供。

## 资源与取消

框架字节预算覆盖编码结果预留及记录缓冲，包含未读流和退休连接的实际持有。用户编码器内部临时分配、业务对象、连接管理与事件记录对象、TLS/QUIC 内部缓冲和 Go allocator 需结合 heap/RSS 单独观察。`MemoryStats` 是租约统计，配置时应为复制与并发保留容量。

`Context` 控制接纳、等待、执行和 IO 取消；用户 `MarshalJSON`、`UnmarshalJSON` 和处理器需要协作退出。同步用户函数可以阻塞，框架会保留对应名额和计费，`Wait/WaitIdle` 可用于观察剩余工作。服务端使用相对剩余预算，不扣除单向网络飞行时间；跨机两端的停止时刻可能不同。

流应消费至结束或显式 `Close`。关闭连接回收 IO 与未读缓冲，进行中的用户编码/解码仍需自行返回。TCP/TLS 共享一个有序记录流，部分写入或坏帧可能影响该连接上的其他调用；QUIC 隔离单个请求流的错误，父连接的拥塞、窗口与故障仍然共享。

## 回执与关闭结果

ACK 确认客户端协议层收到终态标识，业务消费、持久化和提交由应用确认。`DrainWithReport` 封闭接纳后等待在途工作，并分别报告资源静止状态、历史故障和本次新增故障。资源静止可以与交付故障同时出现；累计 `LostTerminals/IncompleteExchanges` 在后续成功调用和重复 drain 后继续保留。截止时间与交付故障同时发生时，应通过 `errors.Is` 分别检查。

预算拒绝次数、CANCEL 观察次数和回执结算结果是不同统计维度，可以重叠。ACK 结算后的迟到消息保持既有累计结果。详细字段定义见 [关闭与故障计数](drain-r9c.md)。

## 发现与控制策略

发现快照以 revision、cluster 和新鲜度作为接纳门槛，健康探测与服务就绪发布由应用组织。快照检查后仍可能发生更新，它提供接纳时的一致性校验。方法公平按服务端配置权重调度；租户身份和 CPU/token 成本需要应用提供额外模型。

自适应控制采样处理器驻留时间，排队与终态收尾另行统计。目标值与固定回退限额应按实际工作量配置，并与合适的静态限额比较；固有耗时、外部依赖和流信用等待都会影响采样。具体策略取舍见 [过载治理](governance-r7c.md) 与 [控制回退](control-r8a.md)。

## 观测与验证范围

决策时间线是有界本地记录，可能采样、覆盖或在锁争用时丢弃事件；缺少事件不能据此判断动作没有发生。序号表示本地捕获顺序，跨 goroutine 的网络因果需结合协议状态分析。本地标识用于请求关联，业务身份、分布式追踪和持久审计由应用管理。

控制台使用同进程的 loopback QUIC 与定时器/槽位负载，p95 包含最近 256 次调用中的失败；控制器 p90 采样处理器驻留时间。历史摘要和累计故障保留在当前进程内，退出后清空。

已保存的验证包括本机 TCP/TLS/QUIC、独立单成员 etcd，以及本地 Linux VM 的内核 netem。真实双机、物理 NIC/WAN、多成员 etcd 分区、小时/天级压力和真实 GPU/vLLM 推理性能尚未验证。本地负载与有限时长观察用于复现机制和内部对照，不能外推生产容量、长期无泄漏或真实推理收益。各阶段的失败、退化与未采纳候选见 [验证索引](verification/README.md)。
